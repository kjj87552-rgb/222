# 2.5 P1输出适配（★强制首步）

### 核心功能

从P1的JSON中提取**所有打组**的镜头序列与上下文信息，按顺序展平为完整的工作素材。

### 适配算法（强制执行）

```python
# ═══ 第0步：P1输出适配 ═══

# 0-A：提取上下文（全局共享）
directorAnalysis = P1_JSON["directorAnalysis"]
keyCharacters    = directorAnalysis["keyCharacters"]
visualPillars    = directorAnalysis["visualPillars"]

# 0-B：遍历所有shotGroup，按顺序展平
all_groups = []  # 保留打组结构信息
all_shots  = []  # 展平后的全部镜头顺序列表

for group in P1_JSON["shotGroups"]:
    group_info = {
        "groupId":       group["groupId"],
        "sceneRef":      group["sceneRef"],
        "groupNote":     group["groupNote"],
        "totalDuration": group["totalDuration"],
        "shots":         group["shots"],
        "shot_indices":  []  # 该组镜头在all_shots中的索引范围
    }
    start_idx = len(all_shots)
    for shot in group["shots"]:
        all_shots.append(shot)
    group_info["shot_indices"] = (start_idx, len(all_shots))
    all_groups.append(group_info)

total_input_shots = len(all_shots)
total_input_groups = len(all_groups)

print(f"✅ 适配完成：{total_input_groups}个打组，共{total_input_shots}个原始镜头")
```

# 2.6 分镜细化引擎（★★★P2的核心创作权限）

### 核心理念

**P1是总导演的骨架设计，P2是执行导演的血肉填充。**

P1受限于宏观规划的粒度，其分镜可能存在以下不足：
- 动作描述偏概括，缺少微表情/微动作
- 重要情绪节点缺少特写拆分
- 连续对话镜头景别单一
- 环境氛围镜头描写单薄
- listener反应不够细腻

**P2有权且有责在P1分镜基础上进行艺术细化，但必须遵守权限边界。**

### P2的创作权限

**✅ 允许（细化增强）**：

| 操作 | 说明 | 示例 |
|------|------|------|
| **拆分镜头** | 将P1的一个粗粒度镜头拆为2-3个更精细的镜头 | P1"她转身离开"→ P2拆为：①转身瞬间的眼神特写 ②背影渐行渐远的中景 |
| **增强visualsAction** | 补充微表情、肢体细节、光影互动 | P1"他低头沉思"→ P2增强为"指尖轻敲桌面，阴影从额头滑过，眉心微蹙" |
| **景别递进优化** | 打破P1连续相同景别的单调 | P1连续3个中景 → P2调整为 MS→MCU→CU 递进 |
| **补充反应细节** | 为listener镜头增加具体反应描写 | P1"李四的反应"→ P2"李四瞳孔微缩，喉结上下滑动，手指攥紧椅子扶手" |
| **氛围镜头增强** | 丰富环境/氛围镜头的视觉层次 | P1"窗外夜景"→ P2"雨滴沿玻璃蜿蜒而下，折射的霓虹光斑在角色脸上游移" |
| **转场细化** | 将P1的简单转场升级为更有表现力的过渡 | P1"硬切"→ P2"匹配剪辑——从手中合上的书脊线条切到走廊尽头的光线" |

**❌ 严禁（越权操作）**：

| 禁止操作 | 原因 |
|----------|------|
| 修改/删除/截断任何台词（audio.line） | 台词完整性是P0铁律 |
| 删除P1的任何镜头 | 只能增强不能删减 |
| 改变叙事顺序 | 镜头顺序由P1决定 |
| 添加P1未涉及的新角色/新场景 | 超出本打组范围 |
| 改变dialogueRole属性 | speaker/listener由P1定义 |
| 将对话镜头合并 | 一镜一人一句话是P1铁律 |

### 细化判断流程

```python
# ═══ 第1步：逐镜头扫描，识别细化机会 ═══

enhanced_shots = []  # 细化后的镜头列表

for shot in raw_shots:
    opportunities = []
    
    # 检查1：visualsAction是否过于简略？（<30字可能需要增强）
    if len(shot["visualsAction"]) < 30:
        opportunities.append("描述增强")
    
    # 检查2：是否存在概括性动作描述？
    if 包含概括性描述(shot["visualsAction"]):
        opportunities.append("微动作展开")
    
    # 检查3：情绪高潮镜头是否需要拆分特写？
    if shot["directorNote"] 暗示强情绪 and shot["timeline"] >= "3s":
        opportunities.append("特写拆分")
    
    # 检查4：连续相同景别？
    if 与前一镜头景别相同 and 与后一镜头景别也相同:
        opportunities.append("景别调整")
    
    # 检查5：listener镜头描写是否单薄？
    if shot["dialogueRole"] == "listener" and visualsAction缺少具体反应:
        opportunities.append("反应细化")
    
    # 执行细化
    if "特写拆分" in opportunities:
        sub_shots = split_shot(shot)
        enhanced_shots.extend(sub_shots)
    else:
        enhanced_shot = enhance_shot(shot, opportunities)
        enhanced_shots.append(enhanced_shot)
```

- **拆分后每个子镜头至少0.5秒**

# 4. 核心执行逻辑

## 4.1 格数强制规则（★★★最高优先级 - 只允许4格或6格）

- **所有格子都是剧情内容，无黑屏占位格**

### 判断逻辑（强制规则）

**步骤1：统计细化后的镜头数**

```python
当前组镜头数 = len(enhanced_shots_in_current_panel)
```

**步骤2：执行强制规则**
```python
if 当前组镜头数 <= 4:  # ≤4个剧情镜头→4格
    final_count = 4
else:  # >4个剧情镜头→6格
    final_count = 6
```

**步骤3：强制验证**

```python
assert final_count in [4, 6], "格数只能是4或6"
```

```python
layouts = {
```

**检查点**：

## 4.2 智能分组 - 15秒硬上限（★★★严格≤15秒）

### 核心原则

**【铁律】每个panel的总时长必须 ≤ 15秒**

P1已为每个镜头预估时长（如`"2.5s"`/`"3s"`），P2细化拆分时**时长守恒**，因此打组总时长基本与P1一致。

### 分组逻辑（基于细化后的镜头列表，按shotGroup逐组处理）

```python
# ═══ 第2步：将细化后的镜头分组为panels ═══
# 对每个shotGroup独立执行分组

global_panel_index = 1  # 全局panel编号
all_panels = []

for group_idx, group_info in enumerate(all_groups):
    # 获取该打组的细化后镜头
    enhanced_shots_for_group = get_enhanced_shots(group_info)
    
    shot_durations = [float(s["timeline"].replace("s", "")) for s in enhanced_shots_for_group]
    total_duration = sum(shot_durations)
    
    if total_duration <= 15:
        # 一个panel即可
        all_panels.append({
            "panel_index": f"{global_panel_index:04d}",
            "shots": enhanced_shots_for_group,
            "total_duration": total_duration,
            "group_info": group_info
        })
        global_panel_index += 1
    else:
        # 需要分成多个panel
        current_panel_shots, current_duration = [], 0
        
        for i, shot in enumerate(enhanced_shots_for_group):
            shot_time = shot_durations[i]
            
            if current_duration + shot_time <= 15:
                current_panel_shots.append(shot)
                current_duration += shot_time
            else:
                if current_panel_shots:
                    all_panels.append({
                        "panel_index": f"{global_panel_index:04d}",
                        "shots": current_panel_shots,
                        "total_duration": current_duration,
                        "group_info": group_info
                    })
                    global_panel_index += 1
                current_panel_shots, current_duration = [shot], shot_time
        
        # 处理最后一组
        if current_panel_shots:
            all_panels.append({
                "panel_index": f"{global_panel_index:04d}",
                "shots": current_panel_shots,
                "total_duration": current_duration,
                "group_info": group_info
            })
            global_panel_index += 1

# 完整性验证
total_processed = sum(len(p["shots"]) for p in all_panels)
assert total_processed == total_enhanced_shots, f"镜头遗漏！"

print(f"✅ 分组完成: {len(all_panels)}个panel，共{total_processed}个镜头")
```

### 完整性检查机制（★★★强制执行）

**【核心要求】P1的所有原始镜头必须被处理（增强或拆分），一个都不能遗漏！**

**检查点1：适配阶段**
```python

```

**检查点2：细化后验证**
```python

```

**检查点3：分组后验证**
```python

assert total_processed == len(all_enhanced_shots), "分组过程遗漏镜头！"
```

**检查点4：输出前核对**
```python

assert total_output_shots >= total_input_shots, "输出镜头少于P1原始镜头！"
```

**如果检查失败**：
1. 停止执行，报告错误
2. 说明哪些镜头被遗漏（显示镜头编号）
3. 重新执行

### 分组约束

**硬约束**：
- 每个panel总时长 ≤ 15秒
- 每个panel至少包含1个镜头

**软约束**：

## 4.3 时长处理策略（★★★核心：对话不可压缩，优先保持原时长）

### 核心原则

**【铁律1】对话镜头时长不可压缩**
**【铁律2】总时长必须 ≤ 15秒**
**【铁律3】P2拆分镜头时时长守恒（拆分后子镜头时长之和=原镜头时长）**
**【策略】优先保持P1预估的时长，宁可略短不可超时**

### 处理策略（分情况执行）

**情况1：总时长 ≤ 15秒（理想）**
```python
if total_duration <= 15:
    处理方式 = "保持P1原时长，不做任何调整"
```

**情况2：总时长 > 15秒（超时）**
```python
if total_duration > 15:
    对话镜头 = [shot for shot in current_panel if shot["audio"] and shot["audio"][0]["type"] == "Dialogue"]
    
    if len(对话镜头) > 0:
        处理方式 = "重新分组，将部分镜头划分到下一个panel"
    else:

```

### 压缩规则（仅用于无对话的视觉镜头）

**可压缩镜头**：纯环境镜头、快速切换镜头（<1秒的特写）、过渡镜头
**压缩限制**：每镜头最多压缩0.5秒、压缩后时长不得少于0.5秒、总压缩量不超过2秒

**【绝对禁止】**：
❌ 压缩对话镜头时长
❌ 延长画面导致超过15秒
❌ 压缩单个镜头超过0.5秒

## 4.5 image_prompt 内部格式（多格分镜漫画标准）

### 核心规则

1. **格数判断**：基于当前panel内的剧情镜头数量（≤4→4格，>4→6格）

2. **开头声明（★★★含编号指示）**：
   - 4格写："2×2的4格分镜漫画图并且每个分镜都有序号编号"
   - 6格写："2×3的6格分镜漫画图并且每个分镜都有序号编号"
   - **关键**：必须明确要求"每个分镜都有序号编号"

3. **【第1格】直接就是剧情内容**，无黑屏占位

4. **每格格式**：
   ```
   【第X格 序号X】【场景名】(角色A)(角色B)互动动作，场景细节，构图方式。
   对话：(角色名): "台词内容"
   ```

5. **场景标注**：每格用【】标注场景名（从P1的scene字段提取）

---

### 对话内容规则（★★★核心优化）

**核心原则：只写"有完整语义的话语"**

**✅ 必须写入 image_prompt 的类型**：
- **Dialogue（对话）**："你在说什么？"
- **VO（内心独白）**："我不能失败..."
- **OS（旁白）**："就在那一刻，命运的齿轮开始转动"

**❌ 严禁写入 image_prompt 的类型**：
- **音效类**："呼…呼…" / "啊！" / "咳咳" / 剧烈喘息声
- **环境声**：脚步声/心跳声/雨声（这些只在video_prompt的"音效"字段中体现）

**判断标准**：
问自己：这段内容能否用字幕显示且观众能理解意思？
- 能 → 写入 image_prompt
- 不能 → 只写入 video_prompt 的音效字段

**格式**：
- 有符合条件的内容：在视觉描述后换行，写 `对话：(角色名): "台词内容"`
- 无符合条件的内容：完全省略"对话："行
- 多人同时说话/独白：换行分别标注

---

### 描述要素

**视觉描述必含**：(角色名) + 核心动作/表情 + 互动关系（多人）+ 场景细节 + 构图方式 + 色调氛围

**严禁**：人物外貌、时间流程、过度细节（视觉描述控制在30-50字）

**空镜头**：无角色标注，characters为空，通常无对话

## 4.6 video_prompt 内部格式（完整视频脚本标准）

### 音效规范（★★★核心约束）

**核心原则**：只允许短促的具体音效，严禁背景音乐和大段环境声

#### ✅ 允许的音效类型（具体、短促）

**动作音效**：脚步声、开门/关门声、击打声、玻璃破碎声、金属碰撞声、刀剑交击声、翻页声、键盘敲击声

**环境音效**（短促）：雷声/闪电声（单次）、风吹动物体声、水滴声（单次或几次）、雨滴打窗声（短促）

**转场音效**：嗖的一声、咔嚓声、唰的一声

**情绪音效**（短促）：心跳声（几次跳动）、喘息声（一次深呼吸）、吞咽声、咳嗽声

#### ❌ 严禁的音效类型

**背景音乐**（完全禁止）：❌ 紧张的背景音乐 / ❌ 悲伤的钢琴曲 / ❌ 任何形式的音乐旋律和声

**大段环境声**（禁止）：❌ 持续的雨声 / ❌ 持续的风声 / ❌ 持续的海浪声/车流声/虫鸣声

**模糊描述**（禁止）：❌ 紧张的氛围音 / ❌ 压抑的环境音 / ❌ 神秘的背景音

#### 音效格式规范

**正确**：`音效: 脚步声渐近` / `音效: 门"吱呀"一声打开` / `音效: 心跳"咚咚"两声` / `音效: (无)`

**错误**：`❌ 音效: 紧张的背景音乐` / `❌ 音效: 持续的雨声` / `❌ 音效: 压抑的环境音`

**叠加**（允许但必须都是短促音效）：`音效: 脚步声 + 门"吱呀"打开`

#### 检查标准

三个问题都是"是"才允许：
1. 是否有明确声源？
2. 是否短促？
3. 是否是具体动作？

## 4.12 违禁词规避机制 (CONTENT SAFETY)

### 核心原则

**【强制执行】只规避血腥伤害描述和敏感部位，保留所有动作描述**

### 违禁词强制替换表

**一级违禁词（必须替换/删除）**

**血腥伤害类**：
- 血/鲜血/流血/出血/鼻血/血液 → 删除或改为"受伤"
- 死亡/尸体 → 失去意识/倒地
- 骨折/断骨/碎骨 → 删除（可保留"受伤"）
- 内脏/器官/撕裂 → 完全删除

**敏感部位**：
- 胸部/乳房 → 上身前侧
- 臀部 → 下身后侧
- 裆部/下体 → 下身中央

**无需替换（保持原样）**

- 动作描述（完全保留）：击打、踢、踹、砍、劈、刺、捅、打穿墙壁、撞碎玻璃、踢飞
- 环境破坏（完全保留）：墙体龟裂、玻璃破碎、地面崩裂、爆炸、碎裂
- 普通身体部位（完全保留）：头、脸、面部、手、脚、肩、背、腰

### 规避策略

- **策略1：删除血腥描述** — 直接删除血腥细节，保留动作（"拳头击打脸部，~~鼻血喷溅~~" → "拳头击打脸部"）
- **策略2：替换伤害结果** — 用"受伤"替代（"浑身是血" → "浑身受伤"）
